Apple Photos metadata integration for Open Brain.

This directory holds a **local-only** JSON cache of metadata from Jeff's Apple Photos library. The cache lets Claude answer questions about when/where photos were taken, who is in them, and what albums/keywords they carry — without touching the pixels.

## Files

- `photos-index.json` — the metadata cache. **Gitignored** (see root `.gitignore`). Generated by `scripts/photos_update_index.py`. Contains UUID, timestamp, GPS, macOS Places name, albums, keywords, face-cluster persons, favorite/screenshot flags, original filename, and dimensions for every non-hidden, non-deleted photo.

## Why gitignored

Photo metadata is sensitive. The index includes GPS for every photo Jeff has taken. Even if this repo stays private, the Open Brain pattern is a prototype for systems built for Eos Automations clients — personal data never belongs in git. Same rule as `Location History/archive/`.

## Prerequisites (one-time setup)

### 1. Install osxphotos

```bash
pip3 install osxphotos
```

### 2. Grant Full Disk Access

Apple Photos stores its database in a protected location. Any process that reads it needs Full Disk Access.

**System Settings → Privacy & Security → Full Disk Access → enable for:**
- The terminal you run scripts from (iTerm, Terminal.app, VS Code's integrated terminal — whichever you use).
- The Claude Code app, if you want Claude to invoke the scripts directly.

**FDA is per-process.** If you run scripts from iTerm but Claude Code is a separate app, both need it. If Claude is running inside iTerm, the iTerm grant is enough.

Verify the grant worked:

```bash
python3 -c "import osxphotos; print(len(osxphotos.PhotosDB().photos()))"
```

A number = good. An error about "operation not permitted" or "database is locked" = FDA isn't granted yet.

## Day-to-day use

### Build or refresh the index

```bash
python3 scripts/photos_update_index.py          # quiet
python3 scripts/photos_update_index.py --verbose
```

This is idempotent — overwrites `photos-index.json`. Run it whenever you want fresh data (after a trip, after culling, etc.). It's also invoked by the Open Brain updater.

### Query by date

```bash
python3 scripts/photos_query.py 2026-04-18
python3 scripts/photos_query.py 2026-04-01 2026-04-18 --summary
python3 scripts/photos_query.py 2026-04-18 --json
python3 scripts/photos_query.py 2026-04-18 --gps-only
```

### Query by entity

```bash
python3 scripts/photos_for_entity.py "events/AI Workgroup 2026-04-18.md"
python3 scripts/photos_for_entity.py "Other Entities/Garden.md" --date-fuzz-days 0
```

### Rank candidates (for dates with lots of photos)

`photos_query.py` dumps every photo in the window. `photos_candidates.py` narrows it to a ranked shortlist using Apple's own ML signals (curation, overall, failure), your favorite flag, face-tag count, burst dedup, and temporal/GPS clustering.

```bash
python3 scripts/photos_candidates.py 2026-03-22 --top 5
python3 scripts/photos_candidates.py 2026-03-22 --top 5 --explain         # scoring breakdown
python3 scripts/photos_candidates.py 2026-03-22 --labels "Water,Beach"    # scene filter
python3 scripts/photos_candidates.py 2026-03-22 --person "Tom"            # face filter
python3 scripts/photos_candidates.py 2026-03-22 --location "Siesta"       # place/body-of-water filter
python3 scripts/photos_candidates.py 2025-09-01 2026-04-18 --text "receipt"  # OCR text search
```

Dedup defaults: 60s + 25m GPS clusters collapse to one representative; bursts collapse to `burst_key_selected` (or `burst_default_pick`, or highest-scoring member). Screenshots excluded by default (`--include-screenshots` to include). Pass `--no-dedupe` to see every photo in ranked order.

**Scoring:**
```
rank = (favorite ? 1.0 : 0)
     + 1.0 * score.curation
     + 0.5 * score.overall
     - 0.5 * score.failure
     + 0.1 * len(persons)
     + 0.2 * (matching --labels count)
```

Apple's scoring skews toward well-lit portraits of smiling people. Documentary shots, abstract work, deliberate grain, etc. may rank low. Weights are conservative starting points — tune after real use.

### Export a single photo for vision

```bash
python3 scripts/photos_export.py <uuid>                  # preview (~1 MB)
python3 scripts/photos_export.py <uuid> --size original  # full resolution
```

The script prints an absolute path under `tmp/photo-exports/` — that directory is gitignored and can be cleared at any time.

## Vision policy

**Metadata first, pixel analysis sparingly.** The cached metadata answers most questions. Opening a photo and feeding it to Claude's multimodal vision is token-heavy and slow, so it's reserved for:

- Explicit requests ("describe this photo," "read the whiteboard," "OCR the receipt").
- A single specific photo where metadata left a genuine gap.

It is **not** used for:
- Location / date / count queries — GPS and timestamps answer those.
- Listing or filtering by album, keyword, favorite, persons, screenshot, or place.
- Entity correlation — `photos_for_entity.py` output is metadata only.
- Bulk "describe everything from X day" requests — those get negotiated down to a specific candidate first.

The full rubric lives in [`.claude/skills/what-did-i-see/SKILL.md`](../.claude/skills/what-did-i-see/SKILL.md).

## Known gotchas

- **"Optimize Mac Storage"** — if enabled (Photos settings), some originals live only in iCloud. `photos_export.py` falls back to a local preview when the original isn't on disk. Preview is ~1 MB and fine for most vision tasks; request `--size original` only for OCR of small text.
- **Library-in-flight** — if Photos.app is actively importing, the SQLite database may be locked or mid-write. Just rerun the script.
- **macOS upgrades** occasionally change the Photos DB schema. osxphotos tracks this, but a major macOS bump may need `pip3 install -U osxphotos`.
- **Screenshots are included.** They have `screenshot: true` in the JSON. Skills note this so a UI screenshot isn't treated as "Jeff was at a real location."
- **Hidden + Recently Deleted are excluded** from the index by default. There is no flag to include them — that was the design choice.

## Privacy note on `detected_text`

The index includes `detected_text` per photo — Apple's on-device OCR of every piece of visible text in every photo you've taken. Receipts, whiteboards, road signs, screenshots of messages, book pages, name tags, anything. This unlocks things like "find the receipt from Target" without a vision call, but be aware: the gitignored local cache contains a searchable copy of that text. It never leaves the machine (not in git, not uploaded anywhere) — but it's there.

OCR is also imperfect. Apple occasionally returns noise (texture patterns parsed as digits, partial words, ghost text from backgrounds). Treat `detected_text` as a search *index*, not a verbatim transcript. If the answer matters, open the specific photo with vision to confirm.
